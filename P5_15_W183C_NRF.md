## Blocked on Planner

Nothing blocks. Five points for the Planner:

1. **The binding tolerance is my choice; please confirm it or change it before spec v1 / W184.**
   - The harness flags an hour as binding on a side when that side's expected interface P is ≤
     `NRF_BINDING_TOLERANCE_MW = 1e-3` MW (1 kW).
   - It is declared in `p515_s44_campaign_harness.py` l. 397–400 and recorded in every NRF record.
   - Each recorded hour carries the TSO and DSO values, so a different threshold can be applied afterwards to the hours
     already recorded. Hours above 1 kW on both sides are not recorded individually; only the per-node minima are.
2. **What "binding hours" measures at more than one scenario.** As ruled, the binding hours are read from the
   *expected* interface P (`p_int_tso_expected_mw` / `p_int_dso_expected_mw`).
   - At SRP1's one scenario, the expected value equals the per-scenario row body.
   - Above one scenario, an expected value ≥ 0 does not show which scenario rows bind.
   - The record therefore also carries, per block, the minimum NRF row body in MW and the number of row indices with
     body ≤ tolerance (`row_counts_per_block`). Please confirm which of the two the E3 report should read.
3. **W183a's test script must not be re-run as it stands.** Its T4 asserts that production has *no* NRF marker, which
   is now false by design. Gate 5 below is the inverted T4.
4. **Scope of the row: three paths do not carry it, as ordered.**
   - The hierarchical TSO builder in `_run_operational_planning_hierarchical`, l. 4676.
   - The uncoordinated path `_run_operational_planning_without_coordination`, l. 8785. Its source is pinned, and
     W116's arm carries its own row.
   - The order names only the coordinated TSO builder and the two DSO initialisation builders.
5. **W183f.** The production and harness hashes have changed (listed below). As a quick check outside the gate artifacts,
   I imported the two-cycle gate `p515_s53_srp1_bitwise_gate.py` and called its `combined_code_presence()` on the
   changed code: **57 / 57 checks True**, including the `model_construction_helpers.py` file pin and the two pinned
   function sources; guard 0. I did not run the gate itself.
